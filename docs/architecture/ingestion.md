# SES inbound ingestion

The implemented worker consumes a **raw SNS delivery** SQS body containing an SES S3-action notification, archives that body, records the message and recipient states in PostgreSQL, reads the original S3 bytes once, uses HTTP upload, and calls `Email/import` separately for each destination account. Recipients are processed sequentially to bound memory; the original message and an upload buffer still need to fit in worker memory. This is a local implementation, not a production go/no-go proof: real SES, SNS, SQS, S3, B2, the production proxy, credentials, permissions and failure behavior have not been exercised. Real AWS calls require separate authorization.

## Contract and routing

AWS describes `receipt.recipients` as “the envelope RCPT TO addresses” matched by the rule, and the S3 action provides the “raw, unmodified email”. See [notification contents](https://docs.aws.amazon.com/ses/latest/dg/receiving-email-notifications-contents.html) and [S3 action](https://docs.aws.amazon.com/ses/latest/dg/receiving-email-action-s3.html). Fixtures follow these descriptions, not captured AWS events. `mail.messageId` is the SES identifier; `receipt.action.objectKey` is used as supplied, including any prefix. Processing time accepts both the documented string and the number in AWS examples. All five verdicts must be present and valid: all PASS delivers to inbox; FAIL, GRAY or PROCESSING_FAILED imports into the configured quarantine mailbox. Unknown recipients are recorded as rejected after SES acceptance, not bounced. Aliases are normalized case-insensitively and grouped by configured destination, including Bcc and multiple domains.

Configure one receipt rule whose notification covers **all intended envelope recipients** for a message. Notifications from separate rules can arrive after the first notification has been processed and its buffer object deleted; the worker cannot infer future recipients. Queue and SNS policies must restrict publishers, raw delivery must be enabled, and the configured bucket, topic and buffer prefix must match. Do not enable SES client-side message encryption: ordinary S3 GET does not decrypt it. Transport, storage encryption, access control, backups, retention and restore procedures remain operator responsibilities.

## Durability and failure handling

A notification is copied to the configured S3-compatible archive before PostgreSQL processing or SQS acknowledgement. This protects it after the worker has received it, including after a later SQS expiry. **It does not protect a notification lost or expired before the worker receives it.** An independent durable SNS subscriber/archive and its recovery path are required to close that gap before production. Archive and buffer must be independently durable, protected from deletion and retained long enough for recovery; B2 has not been tested. If the archive is unavailable, the message is retried and not acknowledged.

The ledger stores the notification as JSON and records each resolved destination and its envelope addresses. A redelivery uses those durable destinations even if routing has changed. An atomic claim records an owner and a ten-minute lease; the worker renews it every minute. Expired claims, including pre-migration claims without timestamps, become `uncertain`, never automatically retryable. Completion is conditional on the original owner, so an expired worker cannot overwrite recovery. Unknown recipients are durably rejected and terminal. The buffer is removed only after every known destination has a confirmed import (including quarantine) and all other recipients are rejected. Deletion and SQS acknowledgement failures can be retried safely.

JMAP and PostgreSQL cannot commit atomically. A lost or timed-out import response becomes `uncertain` and leaves the SQS message unacknowledged and the buffer intact. Imports carry a deterministic per-recipient keyword and the SES mail timestamp as `receivedAt`. Replay searches the target account for that keyword and confirms the timestamp at Stalwart’s one-second storage precision, the Message-ID when present, and size and SHA-256 of the downloaded original bytes. Exactly one matching message is recorded as imported or quarantined. No match, multiple matches, a move out of the destination mailbox, changed metadata, or an unavailable mailbox remains uncertain and makes replay fail. Absence alone does not prove that a delayed server-side import will never commit, so replay does not blindly change it to failed or retry it. Definitive import rejections are recorded as failed; infrastructure failures do not consume the per-recipient attempt budget. Messages imported before this marker was introduced, or whose marker or timestamp was changed, may require operator investigation. JMAP itself provides no exactly-once transaction with the ledger.

SQS visibility starts at five minutes and is extended every minute while handling a message. Failure delays start at one minute and double to an hour; AWS and local queues allow 100 receives and retain messages for 14 days. A prolonged outage can still exhaust retention or reach the DLQ, so alert on both and retain the archive. JMAP requests have a 120-second deadline including response bodies; buffer and archive SDK clients use connection and request deadlines, and S3 body reads have a deadline. Timeout during import is ambiguous. Configure and monitor the DLQ, backlog and replay scheduler independently.

## Running and recovery

Run `pnpm --filter @opensuite/ingest start` for the worker or `pnpm --filter @opensuite/ingest start replay` for reconciliation. Supply `DATABASE_URL`, `INBOUND_BUCKET`, `INBOUND_QUEUE_URL`, `INBOUND_TOPIC_ARN`, `INBOUND_BUFFER_PREFIX`, `ARCHIVE_BUCKET`, `ARCHIVE_PREFIX`, `INGEST_ROUTES` and `INGEST_DESTINATIONS`. Routes are JSON objects with `address` and stable `destination`; destinations have `id`, JMAP `origin`, `authorization` and the quarantine mailbox ID `quarantineMailbox`. When Stalwart advertises a public URL but the worker must use an internal origin, set `rewriteSessionUrls: true` on that destination. This server-side opt-in rewrites the advertised API, upload and download origins to the configured JMAP `origin`, retaining their paths and queries; only use it for a trusted server. Without it, cross-origin endpoints and redirects are rejected. Store these credentials in a protected secret store and inject them only into the worker. `AWS_REGION` defaults to `eu-north-1`; SDK default credentials are used for the buffer and queue. `AWS_ENDPOINT_URL` enables LocalStack. `ARCHIVE_ENDPOINT_URL`, `ARCHIVE_REGION`, `ARCHIVE_ACCESS_KEY_ID` and `ARCHIVE_SECRET_ACCESS_KEY` configure the archive independently. `INGEST_MAX_ATTEMPTS` defaults to 5 and `INGEST_AGE_SECONDS` to 3600.

Replay lists archive notifications and buffer objects, resets retry counts only for definitively failed recipients, and reprocesses archived envelopes. It continues replay if buffer listing fails but reports a failure because orphan detection was incomplete. It emits `ingest_buffer_without_notification` for orphan objects and `ingest_notification_old` for old archived notifications whose buffer remains. It never guesses envelope recipients or verdicts from MIME. An orphan requires an independently recovered SES notification or operator intervention. Expired claims are reconciled as uncertain; a live claim and unresolved uncertain record cause replay to fail and must not be manually reset without establishing the import outcome. Run replay periodically through an external scheduler and alert on its failures, the DLQ and backlog age.

Structured JSON log events are the metrics interface: `ingest_imported` includes `delaySeconds`, and `ingest_failure`, `ingest_rejected`, `ingest_notification_old` and `ingest_buffer_without_notification` include per-process event counts. Export and aggregate these logs as counters and delay distributions; counts reset on restart. Worker logs exclude recipient addresses, message IDs and object keys; access should still be restricted. See [observability](../operations/observability.md) for the status job and alert delivery.
