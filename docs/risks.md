# Risks and open questions

Date: 2026-10-29. All items are open. **Unverified** marks a proposed property or compatibility that has not been established by an integration test. Task references describe work needed to resolve or explicitly disposition each risk, not evidence of completion. The production target and its proof gates are in [ADR 0002](adr/0002-production-target.md).

| **Unverified:** the new Stalwart v1.0.1 release may regress under restart, load or upgrade; documented management schemas, DKIM, JMAP import and authenticated DAV behavior are not proven by the local baseline. Its default mail listeners lack a certificate.                            | **OM-STALWART** exercises the digest-pinned image, schema, permission boundaries, certificates, protocol limits, restarts and client interoperability; document safe upgrades.                                                                                                                                                                                                            |

| **Unverified:** the independent metadata archive receives every necessary notification despite SNS delivery failures or a prolonged VPS outage. MIME alone may omit Bcc. | SES sandbox defaults limit sending to 200 recipients per 24 hours and one per second, with recipient verification restrictions. Removal and production quotas are not automatic.                                                                                                            | **OM-OUTBOUND** handles throttling and queueing, documents sandbox behavior and verifies production access and effective quotas before sending; **OM-OBSERVE** alerts on failures. | A single VPS is not HA: server loss interrupts mailbox/API and sending until a new server is restored. Changes since the last successful backup can be lost; the inbound archive cannot recover arbitrary mailbox or Drive changes.                                                         | **OM-BACKUP** schedules at least daily encrypted backups and tests restores to a new server, recovery time and loss windows; study more frequent intermediate backups. **OM-OBSERVE** alerts on failed or stale backups.                                                                                                                                                                  |

| **Unverified:** Drive's separate database and storage permissions provide sufficient isolation; contention on the VPS or a shared provider may still affect mail.                                                                                                                           | **OM-DRIVE** tests independent service failure, quotas, permissions, resource contention and backup/restore; **OM-OBSERVE** monitors shared resources.                                                                                                                                                                                                                                    |
| **Unverified:** the optional clustered topology achieves its recovery objectives; RocksDB is not a shared cluster data store. ## OpenSuite Pass

Added 2026-10-30. These are open implementation and proof gates, not claims that Pass is deployed. See [ADR 0003](adr/0003-pass.md) and the [threat model and alias contract](architecture/pass.md).

| Risk or unknown                                                                                                                                                                                                                                                                        | Resolution and plan task                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Unverified:** the pinned Vaultwarden image works with PostgreSQL 18.6, isolated credentials and existing secrets/bootstrap on fresh and upgraded installations; a missing or invalid database URL could otherwise select SQLite. Shared Caddy/PostgreSQL failures still affect Pass. | **PASS-COMPOSE** validates the exact digest, PostgreSQL migrations and role isolation, fail-closed configuration, startup/restart, health and operation while the application services are stopped.                                                                        |
| A publicly reachable admin route, spoofed client IP, config override, weak admin token or exposed service port can defeat intended controls; invitation-only onboarding may be impaired without SMTP.                                                                                  | **PASS-COMPOSE** tests all public admin path variants, local tunnel, trusted-proxy boundaries, rate limits, effective configuration, invitation/SMTP behavior and secret handling.                                                                                         |
| The official 1.37.4 image excludes the S3 build feature; B2 endpoint compatibility, permissions, failures and deletion semantics are **unverified**. A successful compile would not establish live storage behavior.                                                                   | **PASS-STORAGE** checks the exact official image, tests B2 read/write/delete, restart, failures, consistency, credentials and restore; absent all proof retain local volume plus restic. A custom build requires a new decision.                                           |
| Loss or compromise of the VPS or B2 account can destroy backups or expose metadata; inconsistent snapshots and lost restic keys can prevent recovery. Changes since the last backup may be lost.                                                                                       | **PASS-BACKUP** implements and tests coordinated PostgreSQL/volume backups, retention, key recovery, alerts and clean-host restore, and evaluates an independently controlled second copy.                                                                                 |
| **Unverified:** exact Bitwarden clients, bundled web vault, passkeys, WebAuthn, WebSockets, mobile push and upgrades work with the pinned server; client protocol changes can break access. The push relay is an external dependency.                                                  | **PASS-COMPAT** tests a versioned client/platform matrix, login, sync, autofill, 2FA/recovery, passkeys, Sends, push and upgrade/rollback; record failures and supported versions.                                                                                         |
| A malicious or compromised vault origin/server can deliver hostile JavaScript; a compromised SPA, shared host, XSS or unsafe cookies can undermine separation and expose secrets or user sessions. No audit has established the boundary.                                              | **PASS-WEB** implements and tests the shell, safe launcher, ephemeral generator, host-only cookies, CSP, origin/CSRF separation and no vault-secret traffic; independent security review remains required.                                                                 |
| Alias keys can be stolen or logged; weak ownership checks, provisioning drift, retry races or unsafe domains may route mail to the wrong user or fail to disable delivery. Envelope identification and safe alias replies are **unverified**.                                          | **PASS-ALIAS** implements scoped hashed revocable keys, authorization, the documented SimpleLogin contract, verified domains, durable reconciliation and recipient mapping; test cross-user isolation, races, queued messages, JMAP identities and outbound authorization. |
| A confusing key lifecycle, cross-origin policy or client incompatibility can expose keys or make alias creation fail; creating an alias in Bitwarden discloses optional website metadata to the mail API.                                                                              | **PASS-ALIAS-WEB** provides issuance, one-time display, rotation, revocation, states and privacy guidance; **PASS-ALIAS** and **PASS-COMPAT** test CORS/CSP and real clients.                                                                                              |
| Security, licensing, client configuration, recovery or operational guidance could overstate assurances; the internal SDK is unstable and legal obligations depend on the exact files reused.                                                                                           | **PASS-DOCS** maintains versioned setup, push, recovery, disclosure, upgrade and license guidance, and records owner/legal and independent security review before any custom vault client.                                                                                 |
