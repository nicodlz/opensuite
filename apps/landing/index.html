Mail first

Mail is the one thing that cannot wait.

In the documented deployment, incoming mail passes through an SES buffer and a delivery ledger before reaching your mailbox. Replay can recover held messages within the configured retention window; operators should monitor the queues and rehearse recovery.

  1. Sender Anywhere on the internet
  2. Inbound relay Accepts the message for you
  3. Durable buffer Retains messages within a window
  4. Ingest ledger Records, delivers, replays
  5. Your mailbox Delivered to Stalwart

Self-host

Your server. Your way.

The production runbook covers a single Ubuntu VPS, DNS, secrets, storage, backups and verification before you switch your mail over. You manage setup, maintenance and hosting costs.

  • An Ubuntu VPS with Docker Compose
  • Git, Node.js and pnpm
  • A domain you control
  • A set of storage buckets (the runbook uses B2)
  • An Amazon SES account for sending and receiving
Read the production runbook

Scale

Start on one server. Make room to grow.

Start with the documented single-server deployment and choose storage for your needs. Plan and verify changes as your usage grows.

  1. Day one

    One server

    The Compose stack brings the suite together on an Ubuntu VPS. Vault is an optional profile.

  2. Growing

    Storage that keeps up

    Files and mail blobs can use S3-compatible object storage. The runbook also configures separate encrypted backups.

  3. Operations

    Plan for growth

    Monitor capacity, backups and mail delivery, and verify any changes to your deployment as your needs evolve.
